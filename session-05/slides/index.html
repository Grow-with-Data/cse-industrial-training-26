The question every AI product hits

“Can it look up the order? And what stops it doing something it shouldn't?” — every team that connects an LLM to real systems

The real work
Tools beat prompts
Anthropic, on building its own agents: “we actually spent more time optimizing our tools than the overall prompt.” OWASP lists excessive agency (too many tools, too much permission) among the top ten LLM risks.

Session 5 · Give it hands · v2

What you'll learn tonight

  1. THE GAPWhy “the model knows” is the wrong mental model: a stable, confident, wrong answer, measured.
  2. A TOOL@tool: name, typed arguments, a docstring written for the model, a plain-data return. What the model actually receives, and two argument names you must never use.
  3. THE LOOPBy hand on a raw model: bind, request, your code runs it, append, ask again. The protocol rules every vendor enforces differently.
  4. THE BOXcreate_agent is that loop. Read its transcript, and set the budget it doesn't set for you.
  5. TOOL DESIGNWhat makes a model pick the right tool, scored on fifteen questions, and what a tool should hand back.
  6. FAILURESRaise or return? Which errors the model can fix, which it can't, and why an error message is a prompt.
  7. TYPED OUTPUTA validated object from an agent, and the strategy you must name.
